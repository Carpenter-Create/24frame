## P0 — Security

### P0-1 — Auth callback concatenates unvalidated `next`

- **Locations:** `src/app/auth/callback/route.ts` (L12, L29, L36).
  Tests in `src/app/auth/callback/route.test.ts` cover relative
  `/queue` only.
- **Evidence:** `const next = searchParams.get("next") ?? "/"` then
  `NextResponse.redirect(\`${origin}${next}\`)` with no allowlist
  (`must start with single /`, reject `//`, `\`, `@`, off-origin).
- **Why (hypothesis):** Common Supabase magic-link pattern; never
  hardened after PKCE/OTP landing was added.
- **Action:** `unify-to-SoT` — allow only same-origin path-relative
  URLs; default `/`.
- **Risk if wrong:** Over-strict allowlist breaks a legitimate
  post-login deep link. Under-strict leaves phishing / odd-parser
  open-redirect after a successful session mint.
- **Note:** String concat (not `new URL(next, origin)`) reduces the
  classic `//evil` case, but there is still **no** validation.

### P0-2 — `/api/cron/*` is not middleware-public

- **Locations:** `src/lib/supabase/middleware.ts` L39–54;
  `src/middleware.ts` matcher (all non-static paths);
  `vercel.json` crons → `/api/cron/transcode-poll`,
  `/api/cron/title-s3-purge`; in-handler auth
  `Authorization: Bearer` + `CRON_SECRET`
  (`transcode-poll/route.ts` L133–149).
- **Evidence:** `isPublic` lists `/login`, `/auth`, `/portal`,
  `/api/portal`, `/api/mobile`, `/api/stripe/webhook`,
  `/sentry-tunnel`. **Not** `/api/cron/*`. Unauthenticated
  requests `redirect("/login")` before the route runs.
- **Why (hypothesis):** Cron auth was added in-route; middleware
  allowlist was never updated. Whether Vercel’s cron dispatcher
  actually hits this middleware in production is a **blind spot**.
- **Action:** `unify-to-SoT` — add `/api/cron` to `isPublic` and
  keep `CRON_SECRET` fail-closed in the handler; **or** document
  proven platform bypass. Do not drop bearer auth.
- **Risk if wrong:** False alarm → unnecessary exemption. True
  gap → transcode poll / S3 purge silently never run (307 to
  `/login`). Founder should confirm one production cron log line
  before treating this as live.

### P0-3 — News ingest SSRF (latent; AWS not created)

- **Locations:** `src/lib/news-ingest.ts` (`fetchNewsFeedXml`,
  `fetchNewsArticleHtml`); `src/lib/news-thumbs.ts`
  (`fetchNewsThumbBytes`). Status:
  `docs/status/CURRENT.md` — Industry News AWS **authorized, not
  created**.
- **Evidence:** Feed URLs come from allowlisted `NEWS_SOURCES`.
  Article / OG / thumb URLs come from parsed items. HTTPS check
  on thumbs; `redirect: "follow"`; no RFC1918 / link-local /
  metadata-IP denylist after DNS.
- **Why:** Ingest must scrape publisher OG images. Isolation
  tests correctly forbid `NEWS_S3_*` invention.
- **Action:** `keep` until founder apply; before Lambda goes
  live, add egress guards (public IPs only, cap redirects). Do
  **not** invent `NEWS_S3_*`.
- **Risk if wrong:** Over-blocking drops legitimate publisher
  CDNs. Under-blocking lets a compromised feed item probe VPC /
  instance metadata from the ingest role (prefix-scoped to
  `news-thumbs/` per runbook).
